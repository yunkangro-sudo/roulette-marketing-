# 단골팅 랜딩페이지 v5 — Cursor 구현 지시서

> 이 문서 하나로 랜딩페이지 전체(카피 + 디자인 시스템 + 인터랙션)를 구현할 수 있도록 정리. HTML 목업(v1~v4)에서 검증된 구조/기능을 텍스트 스펙으로 옮긴 최종본.

---

## 0. 목표 및 타깃

**서비스**: 단골팅 — 소상공인 대상 재방문 게임 마케팅 SaaS
**핵심 포지셔닝**: 손님을 모으는 광고 대행사가 아니라, 이미 온 손님을 다시 오게 만드는 완성된 프로세스
**타깃**: 카페·음식점·미용실 등 오프라인 매장 사장님 (비개발자, 마케팅 전문지식 없음)

**핵심 5문장 (모든 카피의 뼈대)**
1. HERO — 손님을 모으는 게 아니라, 다시 오게 만듭니다.
2. 문제 — 손님이 와도, 광고비는 이미 나갔습니다.
3. 해결 — 게임 한 판이, 다음 방문의 이유가 됩니다.
4. 차별화 — 광고는 고객을 데려오고, 단골팅은 고객을 남깁니다.
5. 전환 — 첫 방문을 만드는 광고에서, 두 번째 방문을 만드는 마케팅으로.

## 4. 히어로 — 3장 시퀀스 (세로 스크롤)

**공통**: 각 장은 뷰포트 전체 높이. 실제 완성된 이미지 에셋을 이미 보유 중 — 아래 에셋 안내대로 그대로 배치할 것 (별도 목업/재구현 불필요, 이미지 원본을 배경 또는 중심 비주얼로 삽입).

### 에셋 안내 (Yoon이 Cursor에 원본 파일 직접 전달 예정)

| 순서 | 파일 역할 | 이미지 내용 | 배치 방식 |
|---|---|---|---|
| 1장 | 통계 카드 | 럭키박스(곰) 캐릭터가 골드 리본을 붙잡은 구도, "12% → 32%" 초대형 숫자, "손님을 모으는 광고 말고, 다시 오게 만드는 게임." 카피, 하단 "단골팅" 로고+"체험해보기" CTA가 이미지 안에 이미 포함됨 | 이미지 자체를 풀블리드로 섹션 전체에 배치 (이미지 안에 카피·CTA가 이미 디자인되어 있으므로 별도 HTML 텍스트 오버레이 불필요). 웹 CTA 버튼은 이미지 위 좌표에 투명 클릭 영역으로 얹어 실제 동작(체험 모달 오픈) 연결 |
| 2장 | 액션 컷 | 도망가려는 손님을 골드 크레인이 붙잡고, 옆에 곰 캐릭터가 반기는 구도. "도망가려던 손님, 붙잡았습니다." + "게임 한 판의 힘. 단골팅." + "궁금하면, 단골팅" CTA가 이미지 안에 포함됨 | 1장과 동일한 방식(풀블리드 + 투명 클릭 영역) |
| 3장 | 미니멀 목업 / 선언형 | 흰 배경, 좌측 폰 목업(단골팅 인형뽑기 게임 화면), 우측 "손님을 모으는 게 아니라 다시 오게 만듭니다" 헤드라인 + 그린 밑줄 강조 + "무료로 시작하기" CTA | 1·2장과 톤이 달라서(밝은 배경) 순서상 마지막에 배치 시 다크 배경 대비 효과가 사라짐 — **아래 "순서 조정 제안" 참고** |

### 순서 조정 제안 (검토 필요)

기존 v4 설계에서는 3장이 다크 배경 + "어떻게?" 스크롤 유도 문구로, 본문(밝은 배경)으로 넘어가는 다리 역할이었습니다. 그런데 실제 3번째 이미지는 다크가 아니라 **화이트 배경의 미니멀 목업**이라, 지금 순서(1 통계 → 2 액션 → 3 미니멀)로 배치하면 다크 전환 효과 없이 바로 본문과 톤이 이어져 버려요.

두 가지 옵션 중 선택해주세요:
- **A안**: 순서를 "2 액션 → 3 미니멀(선언) → 1 통계"로 재배열 — 미니멀 목업의 헤드라인 카피가 마지막에 나와도 자연스럽게 본문 문제제기 섹션과 톤이 이어짐
- **B안**: 순서 그대로 유지하고, 3장 다음에 다크 배경의 짧은 전환 섹션("어떻게?" 문구만 있는 스크롤 유도용 블랙 밴드)을 별도로 추가

**CTA 통일 규칙**: 이미지 안에 이미 그려진 CTA 문구(예: "체험해보기", "궁금하면, 단골팅", "무료로 시작하기")는 이미지 디자인을 존중해 그대로 두되, 실제 클릭 시 동작은 전부 동일하게 "체험하기" 데모 모달 오픈으로 통일. 텍스트가 다르더라도 행동 결과가 같으면 사용자 혼란은 없음.

## 5. 실제 제품 쇼케이스 (히어로 직후)

- 다크 배경, 헤드라인 "손님이 실제로 보는 단골팅 게임 화면"
- 실제 서비스 스크린샷 3개를 가로 배치:
  1. 게임 진입 화면 (01번) — 캡션: "QR 찍고 바로 시작"
  2. 대박 당첨 결과 화면 (05번) — 캡션: "화려하지만 절제된 축하 연출"
  3. 당근마켓 단골 인증 화면 (09번) — 캡션: "고액 당첨 시 리워드 수령 조건"
- 목적: 히어로가 브랜드 무드 위주라, 곧바로 "이게 실제 작동하는 제품"이라는 근거 제시

## 6. 02 문제 제기

**헤드라인**: 손님이 와도 / 광고비는 이미 나갔습니다
**본문**: 네이버, 인스타그램, 당근 광고로 손님을 데려오는 것까지는 가능합니다. 밥을 먹고, 결제하고, 손님은 나갑니다. 그 손님이 다시 왔는지는 광고가 알려주지 않습니다. 사장님은 그 손님이 누구인지도 모릅니다.
**강조 카피(다크 콜아웃 박스)**: 한 번 온 손님을 그냥 보내지 않는 것. 단골팅은 여기서 시작합니다.

---

## 7. 03 포지셔닝 전환

**헤드라인**: 첫 방문을 만드는 광고에서 / 두 번째 방문을 만드는 마케팅으로.
**본문**: 새 손님을 계속 사오는 것만으로는 매장이 성장하기 어렵습니다. 한 번 온 손님이 다시 오고, 또 오게 만드는 것 — 단골팅은 광고 이후의 고객 행동을 설계합니다.

## 8. 04 작동원리 3단계 + Before/After 드래그 비교

**3단계 카드** (각 카드 하단에 해당 실제 화면 스크린샷 첨부):
1. 게임에 참여합니다 — QR 하나면 충분합니다. 로그인 없이, 부담 없이 바로 게임이 시작됩니다. *(스크린샷: 01 진입화면)*
2. 선물을 확인합니다 — 게임이 끝나면 카카오 로그인 한 번으로 결과를 확인합니다. *(스크린샷: 04 결과잠금)*
3. 단골이 됩니다 — 선물을 받으려면 당근마켓 단골 인증이 필요합니다. *(스크린샷: 09 당근인증)*

**Before/After 드래그 비교 컴포넌트**
- 좌우로 드래그(또는 슬라이더 조작) 가능한 비교 위젯
- 왼쪽 레이어: "기존 광고" — 광고 노출 → 클릭 → 매장 방문 → 끝
- 오른쪽 레이어: "단골팅" — 광고 노출 → 게임 참여 → 혜택 → 단골 인증 → 쿠폰 사용 → 재방문
- 구현: `<input type="range">` 값으로 두 레이어 중 하나에 `clip-path: inset(0 {100-value}% 0 0)` 적용, 경계선에 드래그 핸들 아이콘 표시
- 하단 힌트 문구: "← 드래그해서 두 흐름을 비교해보세요 →"

## 9. 05 무엇이 다른가

**헤드라인**: 게임으로 끝내지 않습니다
- 게임이 목적이 아닙니다 — 게임은 고객을 움직이게 만드는 첫 번째 장치입니다.
- 정보 수집으로 끝나지 않습니다 — 카카오 로그인과 당근마켓 단골 전환을 함께 연결합니다. "누가 참여했는가"가 아니라 "누가 다시 오는가"까지 봅니다.

*(주의: "도박이 아니라 선물입니다" 카피는 사용하지 않음 — 도박이라는 단어 자체를 언급하지 않는 것이 안전)*

옆에 01번(진입화면) 스크린샷 배치 — "로그인 없이 바로 시작" 캡션.

## 10. 06 데이터로 증명

**다크 배경 섹션**

**참여 퍼널 (예시)**: 게임 참여 1,000명 → 쿠폰 사용 380명 → 2회 방문 210명 → 3회 이상 방문 126명 → 30일 재방문율 32%
(가로 나열 칩 형태, 화살표로 연결)

**재방문 성과 (예시)**: "12% → 32%" (6개월 누적) / "2,100만원+" (누적 추정 재방문 매출)

옆에 10번(내 럭키박스함) 스크린샷 배치.

각주: ※ 실제 운영 데이터가 축적되기 전까지는 예시·시뮬레이션 수치로 표기합니다.

## 11. 07 매장 손익 시뮬레이션 + ROI 계산기 (핵심 인터랙티브 요소)

**좌측 — 고정 예시 카드**
```
🙋 게임 참여 100명 중, 재방문한 손님        12명
🎟️ 그 12명에게 나간 비용              -120,000원
🛍️ 재방문 12명이 매장에서 쓴 돈        +216,000원
────────────────────────────────
이번 이벤트로 실제로 남은 이익         +96,000원
```
안전장치 카피: 손님이 안 오면 매장은 한 푼도 안 씁니다. 혜택이 나가는 순간은, 이미 손님이 돈을 쓴 뒤입니다.

**우측 — ROI 계산기 (인터랙티브, 다크 카드)**
- 슬라이더: "우리 매장 하루 평균 손님 수" (min 20 / max 300 / step 10 / 기본값 100)
- 계산 로직:
  ```
  재방문 손님 수 = 슬라이더값 × 0.12 (반올림)
  예상 혜택 비용 = 재방문 손님 수 × 10,000원
  예상 재방문 매출 = 재방문 손님 수 × 18,000원
  예상 순이익 = 예상 재방문 매출 - 예상 혜택 비용
  ```
- 슬라이더 조작 시 실시간(oninput)으로 3개 값 갱신
- 하단 작은 텍스트로 가정값 명시: "재방문율 12%, 1인당 평균 혜택 10,000원, 평균 결제 18,000원 가정"

각주: ※ 위 수치는 이해를 돕기 위한 예시 데이터이며, 실제 성과는 매장·업종 조건에 따라 달라질 수 있습니다.

## 12. 08 채널 신뢰 + 매장 운영

**역할 분담 표**
| 요소 | 역할 |
|---|---|
| 당근 | 지역 고객 유입 |
| 카카오 | 고객 참여 및 로그인 |
| 게임 | 참여를 만드는 장치 |
| 쿠폰 | 방문을 만드는 혜택 |
| 데이터 | 재방문 성과 측정 |

옆에 12번(계산대 검증) 스크린샷 배치.

**매장 운영 3단계 카드**
1. 고객이 게임합니다 — QR을 찍고 게임 참여
2. 고객이 단골이 됩니다 — 당근마켓 단골 추가
3. 고객이 다시 방문합니다 — 계산대 QR로 쿠폰 사용

각주: ※ "공식 파트너", "공식 제휴" 등 확인되지 않은 표현은 사용하지 않으며, 단순히 "연동됩니다"로 표현합니다.

## 13. 09 도입 매장 — 후기 캐러셀 (구조만 준비)

## 15. 11 FAQ (8개, 아코디언 또는 리스트형)

1. **게임을 꼭 해야 하나요?** — 아닙니다. 게임은 목적이 아니라, 고객이 자연스럽게 참여하도록 만드는 장치입니다.
2. **손님이 게임을 하고 실제로 다시 오나요?** — 단골팅은 게임 참여자 수만 보지 않습니다. 쿠폰 사용, 2회 방문, 3회 방문, 30일 재방문율까지 추적하도록 설계되어 있습니다.
3. **손님이 게임을 귀찮아하지 않을까요?** — 로그인 없이 바로 시작하는 게임이라, 참여 장벽이 거의 없습니다.
4. **매장 직원이 복잡하게 사용해야 하나요?** — 아닙니다. 고객의 쿠폰 사용 가능 여부를 확인하고, 당근 단골 여부를 확인한 뒤 사용 처리하면 끝입니다.
5. **설치가 어렵나요?** — QR 하나만 매장에 붙이면 됩니다. 별도 장비나 앱 설치가 필요 없습니다.
6. **개인정보는 어떻게 관리하나요?** — 필요한 고객 동의 절차를 거쳐 최소한의 정보만 수집하며, 서비스 운영에 필요한 범위에서만 관리합니다.
7. **예산이 초과될 위험은 없나요?** — 준비한 혜택 수량이 소진되면 자동으로 멈춥니다. 손님이 오지 않으면 비용도 나가지 않습니다.
8. **모든 업종에서 사용할 수 있나요?** — 반복 방문이 매출과 직접 연결되는 업종부터 적합합니다. 카페, 음식점, 미용, 운동, 교육 등에서 특히 효과적입니다.

## 19. 체험하기 모달 — 인터랙티브 데모

**목적**: 손님이 실제로 겪을 게임 경험을 랜딩페이지에서 미리 체험시켜 전환 유도

**플로우**
1. 모바일 프레임 팝업 오픈 → 진입 화면(캐비닛 + "뽑기 시작" 버튼) 표시
2. 버튼 클릭 → 로딩 상태("럭키박스를 찾는 중...") 1.2초
3. 결과 공개 — **당첨만 표시, 꽝은 데모에 넣지 않음** (영업용 체험판에서 부정적 결과는 첫인상에 불리하므로 의도적으로 제외). 랜덤으로 "10,000원 / 2,000원 / 1,000원 쿠폰" 중 하나 표시
4. 결과 화면 하단에 안내: "실제 서비스에서는 카카오 로그인 후 결과가 공개됩니다"
5. "다시 해보기" 버튼으로 1번 상태로 리셋

**주의사항**: 이 데모는 실제 게임 로직(서버 확률 계산)과 무관한 프론트엔드 전용 시뮬레이션. 실제 확률/쿠폰 재고와 연동하지 말 것 — 어디까지나 랜딩페이지 홍보용 체험이며, 실제 참여는 매장 QR을 통해서만 이루어짐을 별도 문구로 구분해도 좋음.

## 21. 아직 보류한 기능 (참고용, 이번 범위 아님)

- **실시간 참여 알림 토스트** ("방금 OO매장에서 당첨됐어요"): 실제 도입 매장 데이터 없이 넣으면 허위 정보이므로, 도입 사례가 쌓인 이후 추가
- **업종별 개인화 헤드라인** (URL 파라미터 기반): 개발 비용 대비 실익이 낮아 초기 버전 범위에서 제외
