# 전국응모 시스템 (본사 연말 대잔치) — 버전2 검토 항목

**작성 기준**: 2026-08-18
**상태**: 아이디어 단계 — 설계·개발 착수 전
**분류**: 버전2(v2) 로드맵 — 지금 버전(v1)에는 포함하지 않음

---

## 1. 컨셉

- 전국 가맹 매장(예: 100개 매장) 어디서든 게임(뽑기)에 참여하면, 매장 즉석 쿠폰과 별개로 **"본사 전국 이벤트" 응모에 자동 참여**된다.
- 매년 **12월 25일** 당첨자를 발표한다.
- 경품 예시 (확정 아님, 매년 조정 가능):
  - 1등 1명 — 최신형 아이폰
  - 2등 2명 — 갤럭시워치
  - 3등 5명 — 신세계상품권 10만원
- 목적:
  - 매장 게임 참여율 상승 (당장의 매장 쿠폰 + 장기적 대박 기대감, 이중 동기부여)
  - 매장 입장에서 "본사가 아이폰까지 주는 이벤트에 무료로 태워준다"는 영업 스토리 확보
  - 지금은 필요 없지만, 추후 카카오 계정 기반 고객 DB를 마케팅에 활용할 여지 확보

## 2. 이미 갖춰진 기반 (재사용 가능한 인프라)

| 항목 | 현재 상태 | 비고 |
|---|---|---|
| 본사/대행사 관리자 권한 | `agency`, `super_admin` 역할이 이미 존재하며 매장 제한 없이 전체 매장 조회 가능 | `lib/admin/session.ts` |
| 손님 식별자 | 카카오 로그인(`kakao_user_id`)이 매장과 무관하게 전국 공통 | 여러 매장 참여 기록을 한 사람 기준으로 합산 가능 |
| 당첨 알림 | 카카오 "나에게 보내기" 발송 인프라 이미 구현 | `lib/kakao/meMessage.ts` (현재는 talk_message 동의 있는 실사용자에게만 발송) |
| 쿠폰/활동 로그 구조 | `coupons`, `activity_log`, `daily_participation_log` 모두 `store_id + kakao_user_id` 조합으로 이미 기록 중 | 매장별 데이터가 이미 분리 저장되어 있어 집계만 하면 됨 |

## 3. 새로 만들어야 하는 것

### 3.1 전국 이벤트 데이터 모델
- 지금 `events`는 매장(store_id) 1개에 종속되는 구조. 매장과 무관하게 돌아가는 "전국 캠페인" 개념이 없음 → 신규 테이블/스키마 필요 (기간, 경품 티어, 응모 조건 등).

### 3.2 당첨자 선정 방식 — 결정 필요
- **응모권 추첨 방식(추천)**: 게임 참여 1회당 전국이벤트 응모권 1장 자동 적립 → 마감일에 무작위 추첨. 구현 난이도 낮고 공정성 이슈도 적음.
- **포인트/방문 합산 순위 방식**: 전체 매장 포인트를 합산해 랭킹. 매장별 포인트 정책 차이로 형평성 문제가 생길 수 있어 비추천.
- 최종 방식은 착수 전에 확정 필요.

### 3.3 본사 관리자용 집계·발표 화면
- 전체 매장 응모 현황을 한 화면에서 보고, 당첨자를 확정·발표하는 관리자 UI 신규 필요.

### 3.4 경품 수령 방식
- 매장 쿠폰처럼 "계산대에서 사용"이 아니라 실물 경품(아이폰, 워치, 상품권)이라 **배송 절차**가 필요.
- 카카오 로그인만으로는 실명·연락처·배송지가 없음 → 당첨자 대상 별도 정보 입력 페이지 필요.

### 3.5 개인정보 수집 동의 항목 사전 정비
- 지금 카카오 로그인 동의 시점에 "전국 이벤트 당첨자 안내 및 경품 배송" 목적이 포함되어 있지 않음.
- 나중에 목적을 추가하면 기존 가입자 전체 재동의가 필요해지므로, **이 기능을 만들기 전에** 동의 항목을 미리 정비해두는 것이 안전.
- "(선택) 마케팅 정보 수신" 항목도 이 시점에 함께 넣어두면, 추후 고객 DB 마케팅 활용 시 재동의 부담이 없음.

### 3.6 형평성 · 어뷰징 방지 규칙
- 매장별 참여자 수 편차(대형 매장 손님이 응모권을 과점하는 문제) → 1인당 응모권 상한 등 규칙 검토.
- 계정 어뷰징(카카오 계정 다중 생성) 방지 및 "부정 응모 확인 시 당첨 취소" 조항 사전 마련.
