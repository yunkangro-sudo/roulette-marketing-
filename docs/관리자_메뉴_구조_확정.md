# 관리자 메뉴 구조 확정 문서

**작성 배경**: 위드픽 관리자 화면 20장을 캡처해서 대조 분석. 우리 메뉴가 이미 심플하게 잘 잡혀있다는 걸 확인했고, 앞으로 기능을 추가할 때 흔들리지 않도록 원칙을 명문화한다.

**중요**: 광고주 메뉴와 슈퍼관리자/에이전시 메뉴는 **서로 다르다.** 역할별 메뉴 목록을 서로 바꿔 적용하지 말 것.

**2026-08 갱신 (1차, 광고주 v2)**: "광고주 메뉴 6개 고정" 원칙은 폐기했다. 광고주 관리자 모드 확장(v2)에서 대시보드·회원
관리가 추가되며 광고주 메뉴가 6개를 넘어섰고, 앞으로도 필요한 기능이 있으면 개수 제한 없이 최상위
메뉴를 추가한다. 남기는 원칙은 "역할 분리"와 "탭/섹션으로 넣을 수 있으면 새 메뉴보다 우선 검토" 정도다.

**2026-08 갱신 (2차, 슈퍼관리자 모드 개편 v1)**: super_admin/agency의 전역 탭(이벤트 관리/성과 리포트/포인트
정책/리워드 관리/쿠폰 관리)을 없애고 "전체 대시보드 / 업체 리스트" 2개로 축소했다. 대신 "대리접속
(Impersonation)" 메커니즘을 도입해, 업체 상세에서 "이 업체로 관리 진입"을 누르면 그 업체의 광고주
화면·메뉴를 그대로 재사용해서 관리할 수 있다 (아래 6번 참고).

**2026-09-01 갱신 (3차, 슈퍼관리자 구독관리 신설)**: 슈퍼관리자/에이전시 전역 메뉴에 "업체 구독관리"
(`/admin/super/subscriptions`)를 추가해 2개 → 3개가 됐다. 검색/필터, 결제(입금) 이력 확인·등록, 입금 확인
처리, CSV 다운로드를 제공한다. 업체 상세 안의 구독 이력 패널(`CompanySubscriptionsPanel`)과 데이터를
공유하되, 전체 업체를 가로질러 한눈에 보는 용도로 별도 최상위 메뉴로 뺐다.

소스: `app/admin/(auth)/AdminNav.tsx`

## 1. 역할별 메뉴 구조 (서로 다름, 혼동 금지)

### 광고주(advertiser) 메뉴

```
대시보드 / 이벤트 관리 / 회원 관리 / 성과 리포트 / 포인트 정책 / 리워드 관리 / 쿠폰 관리 / 계산대 →
```

상단 가로 배치. 자기 매장만 다룬다. 계산대(`/staff`)는 광고주(및 staff)만 바로가기.
"대시보드"(이용기간 현황·KPI)와 "회원 관리"(회원 목록·세그먼트)는 2026-08 v2 확장에서 추가됐다.
쿠폰 발급은 "쿠폰 관리"(`/admin/coupons`) 안에 발급/현황 탭으로 통합됐다 (아래 6번 참고).

### 슈퍼관리자(super_admin) / 에이전시(agency) 메뉴

```
전체 대시보드(/admin/super/dashboard) / 업체 리스트(/admin/companies) / 업체 구독관리(/admin/super/subscriptions)
```

2026-08 슈퍼관리자 모드 개편 이후 매장 전용 화면(이벤트 관리/대시보드/회원 관리/쿠폰
관리/포인트 정책/리워드 관리/성과 리포트)은 전역 탭에서 완전히 사라졌다 — 대신 업체 상세에서
"이 업체로 관리 진입"(대리접속)해서 그 매장의 광고주 화면을 그대로 쓴다. 계산대 바로가기는 **없음**.
"업체 구독관리"는 2026-09-01에 3번째 전역 메뉴로 추가됐다 (이용기간/결제 현황을 업체 단위가 아니라
전체 업체 가로질러 보고 관리하기 위함).

### staff

관리자 상단 메뉴가 없다. `/staff` 계산대만 사용한다.

## 2. 위드픽 대조 분석 — 무엇이 문제였고, 우리가 왜 다른가

| 위드픽 관리자 화면 | 발견된 문제 | 우리 판단 |
|---|---|---|
| 사이드바 20개+ 메뉴, "게임관리/게임이력"이 두 그룹에 중복 | 사이트맵 없이 기능 생길 때마다 아무 데나 추가한 흔적 | 채택 안 함 — 개수를 막지는 않지만, 같은 개념을 두 메뉴로 쪼개거나 아무 데나 추가하지 않는다 (탭/섹션 우선 검토) |
| 게임종류(숫자게임/룰렛가입/룰렛방문)마다 별도 설정 화면 | 같은 개념을 게임마다 따로 관리, 광고주 혼란 유발 | 채택 안 함 — `game_type` 필드로 이벤트 안에서 통합 |
| 당첨자 리스트/쿠폰조회에 손님 **이름+전화번호 평문 노출 + 엑셀 다운로드** | 개인정보보호법 관점에서 명백한 리스크, 목적 외 이용 가능성 | **절대 채택 안 함** — 전화번호는 마스킹, 사장님 직접 열람은 별도 동의 필요 (기존 원칙 유지) |
| 룰렛판 이미지를 430×430px, 화살표 42×63px 등 픽셀 단위로 사장님이 직접 업로드 | 비개발자에게 디자인 제작을 떠넘기는 구조 | 채택 안 함 — 캐릭터/디자인은 시스템이 제공, 사장님은 텍스트/수량만 입력 |
| "게임가능기간"과 "서비스오픈기간"이 별도로 존재 | 비슷한 개념 두 개를 따로 관리, 헷갈림 유발 | 채택 안 함 — "이벤트 노출기간" 하나로 통일 |
| 위치기반 단골 스탬프(GPS 반경 인증) | 별도 인프라, 손님 위치정보 요구 | 채택 안 함 — 예전에 "부담스럽다"고 이미 기각한 사안과 동일 |
| 성별/연령/가입시간대/요일별 등 과도한 인구통계 | 소상공인이 실제로 활용하기 어려운 허영 지표 가능성 | 채택 안 함 — 우리는 세그먼트(신규/활성/이탈위험/휴면) 같은 행동 기반 지표 우선 |
| 채널 가입수/차단수 집계 숫자 | 개인정보 없는 순수 집계치 | 🟡 검토 가능 — 대시보드 참고 지표로 추가 여지 있음, 지금 급하지 않음 |
| 소개쿠폰(추천인 코드) | 친구초대 유사 기능 | 🟡 보류 — FRIEND API 재설계(카카오톡 공유 방식)와 함께 나중에 검토 |

## 3. 원칙

1. **새 메뉴를 넣기 전에 역할을 먼저 정한다.** 광고주도 봐야 하는지, 슈퍼관리자/에이전시만 봐야 하는지. 둘의 메뉴는 다르다.
2. **완전히 새로운 최상위 메뉴 전에 기존 메뉴 안의 탭/섹션으로 넣을 수 없는지 본다.** 메뉴 개수 자체는 고정하지 않는다 — 필요한 기능이면 계속 추가한다.
3. **개인정보(이름·전화번호)는 관리자 화면에 평문으로 절대 노출하지 않는다.** 엑셀 다운로드 같은 대량 추출 기능은 원천적으로 만들지 않는다.
4. **디자인/이미지 제작을 광고주에게 떠넘기지 않는다.** 시스템이 기본값을 제공하고, 광고주는 텍스트·숫자 입력만 한다.
5. **비슷한 개념을 두 가지 이름으로 쪼개지 않는다.** (예: 게임기간 vs 서비스기간 → 이벤트 노출기간 하나로)
6. **위치기반 인증, 과도한 인구통계 등 부담이 크고 활용도가 낮은 기능은 채택하지 않는다.**
7. **화면에서 숨긴 메뉴는 API에서도 막아야 한다.** 네비만 가리고 엔드포인트가 열려 있으면 권한 우회다.

## 4. 이 문서의 용도

새 관리자 기능을 추가하고 싶을 때, 이 문서의 표와 원칙을 먼저 확인한다. "위드픽에도 있던 기능"이라는 이유만으로 채택하지 않는다 — 위드픽에 있다는 것 자체가 오히려 재검토 신호가 될 수 있다.

Cursor 규칙: `.cursor/rules/admin-menu-principles.mdc`

## 5-1. 대리접속(Impersonation) 메커니즘 (2026-08 신규)

super_admin/agency가 매장 전용 화면(대시보드/이벤트/회원/쿠폰 등)에 들어가는 유일한 방법이다.

- 업체 상세(`/admin/companies/[id]`)의 "이 업체로 관리 진입" 버튼 → `POST /api/admin/impersonation/start`
  → `impersonation_log` row 생성 + 세션에 `account.impersonation` 저장.
- 이후 `[lib/admin/session.ts](../../lib/admin/session.ts)`의 `requireAdminAuth()`가 `getEffectiveAccount()`를 거쳐
  **role을 advertiser로, storeId를 대상 매장으로 스왑**해서 반환한다 — 그래서 광고주 전용 API/화면을
  전혀 수정하지 않고 그대로 재사용할 수 있다. 원본(진짜) 계정 정보는 `account.impersonation`에 별도
  보존되어 있어 배너·"나가기"·감사로그에 쓰인다.
- 모든 화면 최상단에 `ImpersonationBanner`가 뜬다: "[업체명] 대신 관리 중 · 슈퍼관리자: [이메일] · 나가기".
  "나가기" → `POST /api/admin/impersonation/exit` → `impersonation_log.ended_at` 기록 + 세션 원복.
- 대리접속 중에는 이용기간 만료 차단(`/admin/expired` 리다이렉트)이 적용되지 않는다 — 만료된 업체를
  들여다보고 처리해야 하는 상황이 더 흔하기 때문. 대신 만료/유예 상태를 정보성 배너로만 안내한다.
- `middleware.ts`: 대리접속 없는 super_admin/agency가 매장 전용 경로(`SUBSCRIPTION_GATED_PATH_PREFIXES`,
  `[lib/admin/subscription.ts](../../lib/admin/subscription.ts)`)에 URL로 직접 접근하면 `/admin/companies`로 리다이렉트한다.

## 5-2. API 권한 점검 (2026-08-14)

광고주가 URL을 직접 쳐도 되는지가 아니라, **API를 직접 호출해도 막히는가**가 기준이다.

| 대상 | 광고주가 직접 호출하면 | 판정 |
|---|---|---|
| `GET/POST /api/admin/companies` | **403** `접근 권한이 없습니다` | 통과 — 화면 숨김 + 서버 강제 |
| `GET/PATCH /api/admin/companies/[id]` | **403** | 통과 |
| `POST /api/admin/companies/register` | **403** | 통과 |
| `POST /api/admin/companies/reset-password` | **403** | 통과 |
| 페이지 `/admin/companies` | 이벤트 관리로 리다이렉트 (advertiser 기준) | 통과 (페이지) |
| 페이지 `/admin/dashboard` | 매장 1곳 전용 화면으로 단순화(2026-08 슈퍼관리자 개편). advertiser 또는 대리접속 중인 super_admin/agency만 렌더, 그 외는 middleware가 `/admin/companies`로 리다이렉트 | 통과 (페이지) |
| 페이지 `/admin/super/dashboard` (2026-08 신규) | super_admin/agency 전용, 그 외는 `/admin/events`로 리다이렉트. `SUBSCRIPTION_GATED_PATH_PREFIXES`에 없어 대리접속과 무관하게 항상 접근 가능 | 통과 (페이지) |
| `GET /api/admin/stores` | 자기 매장 1건만 200 (전체 목록 아님) | 통과에 가깝음 |
| `GET /api/admin/dashboard` (다매장 집계, 구버전) | 비로그인 401, 광고주 403. super_admin/agency만 — 더는 화면에서 안 쓰지만 API는 유지 | 통과 |
| `GET /api/admin/super/dashboard` (2026-08 신규) | super_admin/agency 전용 403 가드 | 통과 |
| `GET /api/admin/dashboard/summary` (2026-08 신규, 2026-08 슈퍼관리자 개편에서 확장) | advertiser(또는 대리접속 중)는 자기 매장만. super_admin/agency는 `?storeId=` 쿼리로 읽기 전용 조회 가능(업체 상세 "요약 현황" 탭) | 통과 |
| `GET /api/admin/members`, `GET/POST /api/admin/coupons`, `POST /api/admin/coupons/remind` (2026-08 신규) | advertiser(또는 대리접속 중) 전용, 자기 매장만. 전화번호는 뒷4자리 마스킹만 응답 | 통과 |
| `GET /api/admin/report?store_id=` | 비로그인 401. 광고주는 세션 매장만 (쿼리 store_id 바꿔도 무시). 2026-08 슈퍼관리자 개편에서 `SUBSCRIPTION_GATED_PATH_PREFIXES`에도 추가되어 대리접속 없는 super_admin은 페이지 접근 자체가 막힘 | 통과 |
| `POST /api/admin/impersonation/start`, `POST /api/admin/impersonation/exit` (2026-08 신규) | raw role이 super_admin/agency 아니면 403. 이미 대리접속 중 재시작 시도 409 | 통과 |
