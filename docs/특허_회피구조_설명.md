# 우리 서비스가 해당 특허 구조와 다른 이유

대상: 변리사 상담 · 내부 공유  
분량: 약 3분  
갱신: 2026-08-14 — 손님 여정을 **게임 먼저 → 결과 잠금 → 로그인으로 해제**로 변경한 뒤 반영

---

## 1. 한 문장 요약

해당 특허가 막는 것은 **「카카오톡 채널에 가입했는지 서버가 확인한 뒤에야 게임을 실행」** 하는 방식이다.  
우리는 **로그인·채널 가입과 무관하게 게임을 먼저 실행**하고, 로그인은 게임이 끝난 뒤 결과를 공개할 때만 쓴다. 채널 가입 여부는 조회하지도 않는다.

---

## 2. 표로 비교

| 구분 | 특허의 방식 | 우리 방식 |
|---|---|---|
| 게임을 하려면 무엇이 필요한가 | SNS 로그인 + **카카오톡 채널 가입** | **아무것도 필요 없음.** QR만 스캔하면 즉시 게임 |
| 로그인은 언제인가 | 게임 **시작 전** | 게임이 **이미 끝난 뒤**, 결과를 보려 할 때 |
| 무엇을 확인하는가 | 카카오톡 **채널 친구(가입) 상태** | 게임이 끝난 뒤, **모든 경품**에 대해 **당근마켓 단골** 여부. 카카오 채널이 아님 |
| 언제 확인하는가 | **게임 시작을 요청한 바로 그 시점** | 게임이 **이미 끝난 뒤**, 계산대에서 사용할 때 |
| 어떻게 확인하는가 | 서버가 카카오 API로 **자동 조회** | 매장 직원이 계산대에서 손님 화면을 **육안으로 확인** |
| 확인 실패 시 | **게임 자체를 시작하지 못함** | 게임은 이미 했고, **경품만 아직 쓰지 못함** |

핵심 차이 네 가지:

1. **게임 실행이 로그인보다 먼저다** — 로그인은 결과 공개 열쇠일 뿐, 게임 실행 조건이 아니다
2. **확인 대상이 다름** — 카카오톡 채널이 아니라 당근마켓 단골
3. **확인 시점이 다름** — 게임 시작 전이 아니라 게임 종료 후 계산대
4. **확인 방법이 다름** — 서버 자동 조회가 아니라 직원 육안 확인

## 3. 우리 코드 근거

2026년 8월 14일, 프로젝트 전체를 검색해 아래를 확인했다.

### 채널 가입 상태를 조회하는 코드가 없다

카카오의 채널 관계 조회 API(`talk/channels`, `ADDED` / `BLOCKED` / `NONE` 등)를 **호출하는 코드는 프로젝트 어디에도 없다.**

실제로 카카오 API를 부르는 곳은 로그인·프로필·친구목록·나에게 보내기뿐이며, 채널 가입 여부 조회는 포함되지 않는다.

| 파일 | 하는 일 |
|---|---|
| `lib/auth/kakao.ts` | 로그인 토큰, 프로필, **유저 친구 목록** (채널 관계가 아님) |
| `lib/kakao/meMessage.ts` | 쿠폰을 카카오톡 **나에게 보내기** |
| `app/api/kakao/channel/friend/route.ts` | 메시지 발송 동의용 **수신 stub**. 게임 실행과 분리되어 있고, 카카오에 채널 상태를 물어보지 않음 |
| `components/play/ChannelCtaScreen.tsx` | 결과 공개 **이후** 선택 안내. 건너뛰기만 있고 조회/기록이 없음 |

### 게임을 막는 조건은 하나뿐이다

게임 흐름은 `app/(customer)/play/[storeId]/PlayFlow.tsx`에 있다.  
시작을 막을 수 있는 조건은 아래 **한 가지로 고정**되어 있다.

1. **활성 이벤트 존재** — 해당 매장에 진행 중인 이벤트가 있는지 (`page.tsx`)

로그인·당일 참여 여부는 게임이 끝난 뒤 `POST /api/games/claim`에서 **결과를 공개할지**만 결정한다.  
채널 가입·구독·친구·팔로우 여부는 이 목록에 없다.

게스트 추첨 API(`app/api/games/play/route.ts`)는 `event_id`만 받으며, `kakao_user_id`도 채널 상태도 검사하지 않는다. 응답은 `{ locked: true }`뿐이고 당첨액은 httpOnly 세션에만 둔다.

고액이든 소액이든, 경품 확인은 게임이 끝난 뒤 `/staff`에서 직원이 `[확인함]` / `[미확인 처리]`를 누르고, 이어서 `[할인 적용 완료]`를 눌러야 사용 처리된다. 카카오 채널 가입 여부는 이 과정에 없다.

원칙 파일: `.cursor/rules/patent-safety.mdc`

## 4. 순서 비교

**특허 방식**

```
로그인
  → 게임 시작 요청
    → 서버가 채널 가입 여부를 자동 조회
      → 가입된 손님만 게임 실행
      → 미가입 손님은 게임 자체를 못 함
```

**우리 방식 (2026-08-14 이후)**

```
QR 스캔
  → 로그인 없이 즉시 게임 실행 (채널·로그인과 무관)
    → 결과는 서버 세션에만 저장, 화면에는 잠금
      → 카카오 로그인 (결과를 보기 위한 열쇠)
        → 이때만 하루 1회 제한 체크
        → 통과 시 결과 공개 + 쿠폰/포인트
          → 채널 추가 안내는 건너뛸 수 있는 선택 사항 (조회 없음)
            → 계산대에서 직원이 당근 단골을 눈으로 확인
              → [확인함] 후 할인 적용
              → 안 되면 게임은 이미 했고 경품만 보류
```

상세 라우트/함수: `docs/손님여정_프로세스_v2.md`

---

## 5. 결론

특허가 보호하는 것은 **게임 실행과 채널 가입을 연결한 것**인데, **우리에게는 이 연결고리 자체가 없다.**  
한 걸음 더 나아가, **게임 실행과 로그인조차 연결하지 않는다.**
